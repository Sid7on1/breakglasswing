### End-user harness metrics

Do not publish a vague composite readiness percentage. Show the observable limits and capabilities:

- **8 / 8 core harness jobs:** project understanding, planning, tool use, parallel agents, isolated
  work, verification, saved sessions, and extensibility are all present.
- **6 built-in providers:** NVIDIA, OpenAI, Anthropic, OpenRouter, DeepSeek, and Google, plus a custom
  OpenAI-compatible endpoint.
- **4 coordinated workers at once:** the shared capacity guard applies across nested workers and
  subprocesses.
- **3 agent levels:** the main agent plus two nested worker layers.
- **130 guarded model/tool cycles per active execution:** a hard circuit breaker, not a promise that
  every job should consume all 130.
- **24 coordinator continuation wakes:** unfinished outcomes can be revisited without an unbounded
  self-loop; three no-progress wakes halt safely.
- **No fixed wall-clock session timer:** provider availability, the user's machine, explicit stop,
  and the safety circuit breakers determine active duration.
- **Saved sessions have no built-in expiry:** users can resume stored project sessions later. Resume
  restores the recent working context rather than replaying an unlimited prompt.
- **7-day automatic interruption recovery window:** eligible crashed worker snapshots can be
  recovered automatically for seven days; ordinary saved sessions remain separately resumable.
- **Free preview:** Bimax currently adds no software subscription charge; users pay their selected
  model provider for usage. Do not call the complete experience free or claim open source until a
  repository license is published.

Public copy should express closeness as `The same core harness jobs, with proof made first-class.`
The comparison concerns orchestration behavior, not model intelligence or output quality.

### Five Bimax proof pillars

1. **The codebase becomes a graph.** Bimax reasons about modules, dependencies, and blast radius,
   not only the files retrieved for the current prompt.
2. **The outcome becomes a contract.** Acceptance criteria and required evidence stay active beyond
   one model response.
3. **Delegation becomes accountable.** Workers receive scope, ownership, dependencies, and expected
   evidence; the parent independently verifies integrated results.
4. **Proof expires when the code changes.** A green check cannot remain authoritative after a later
   mutation invalidates what it covered.
5. **Long work has a recovery path.** Checkpoints, worktree receipts, and bounded recovery preserve
   progress instead of relying only on conversational memory.

## Art direction: Living Build Ledger

The site begins in an open, sunlit natural landscape. A single fine trajectory moves through grass,
cloud shadow, and leaves, then becomes Bimax's terminal cursor and verification rail. Nature is not
decoration: it represents the user's intent becoming structured work. The terminal is the dark,
precise instrument inside that living environment.

This trajectory is the signature element. Do not add competing glassmorphism, 3D blobs, floating
cards, glowing AI brains, or arbitrary particles.

## Exact single-page architecture

### 1. Hero — “Same model. Different harness.”

- Full viewport with the Prisma-style inset frame: `16px` mobile, `24px` desktop, maximum `32px`
  corner radius.
- Hero Flow video fills the frame. Preserve darker negative space on the left and open sky on the
  upper right.

- Monumental `Bimax` wordmark at the bottom, spanning roughly 84% of desktop width.

  Instrument Serif.
- Real install command and a `Watch a real run` action. No email collection in the primary journey.
- The trajectory begins as a sunlit filament through grass and becomes the blinking terminal cursor
  at the end of the hero.

### 2. Proof strip — release truth

A quiet four-cell rail immediately after the hero: current version, supported macOS architectures,
signed/notarized state, and checksum status. Values must come from release metadata. Never present a
security state more positively than reality.

### 3. Harness comparison — how close is Bimax?

Render the central comparison table as horizontally aligned capability rails on desktop and stacked
row cards on mobile. Start with the sentence `The same core harness jobs, with proof made first-class.`
Let visitors switch between `Orchestration`, `Proof`, `Safety`, and `Experience`; keep all rows in the
DOM for accessibility. Every Bimax row links to a real demonstration or technical note. Follow it
with the concrete provider, worker, delegation-depth, duration, recovery, and free-preview metrics.

### 4. Outcome sequence — Ask / Build / Verify

Three full-width chapters, not generic feature cards:

1. **Ask** — wind moves through tall grass while the user's real prompt appears as HTML.
2. **Build** — cloud shadows cross a forest clearing while a real file-change ledger advances.
3. **Verify** — sunlight breaks through the canopy as real checks resolve into evidence.

On desktop, the natural plate occupies two-thirds of the frame and the ledger owns one-third. On
mobile, use the planned portrait crop above the copy. The trajectory connects all three chapters.

### 5. Real run — the dark clearing

The organic world falls nearly silent and the page opens into one full-width real Bimax TUI capture.
Use a deterministic session fixture showing prompt, file changes, tests, and final proof. Let the user
scrub `Ask`, `Work`, and `Verified`. No Flow-generated terminal or invented capability appears here.

### 6. Capability canopy

Five editorial rows use the Bimax proof pillars: code graph, outcome contract, accountable
delegation, expiring proof, and recovery. Each row pairs a Flow still detail—leaf veins, branching
roots, cloud layers, growth rings, regrowth—with a genuine product artifact. The natural analogy
remains visual; copy stays literal and product-specific.

### 7. Trust and installation

A sunlit paper-like field interrupts the dark page. Show credential storage, approval boundaries,
sandbox behavior, provider choice, uninstall steps, and checksums. End with one verified install
command and links to Download, Docs, Changelog, Trust, and Status.

### 8. Closing frame

A short horizon loop with grass moving in the wind. Copy: `Bring the intent. Bimax carries the work.`
The trajectory finishes as a verified check, followed by the footer.
