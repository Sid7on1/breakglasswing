STYLE DNA — BIMAX "TWO MINDS, ONE BUILD" · screen-native product cinema
Look: photoreal, cinematic. A warm near-black graphite world (#0C0D0B). The ONLY accent colours are ember #E0623A (the human's intent) and teal #3F8C7C (the build & verification). Low-key theater lighting — the screen's own glow is the key light, one warm rim from off-frame, volumetric haze holding the light, deep vignette falling to pure black at the edges.
Camera: physical macro / probe cine lens, shallow depth of field, 180° shutter motion blur. ONE slow, deliberate, continuous move per clip — no hard cuts. The camera is always gently descending: a downward / into-the-screen drift.
Motion feel: calm, confident, inevitable. Ease-in-out. Nothing frantic. The real UI keeps its exact layout, fonts and text — it is lit and moved, never redrawn.
Audio (Veo native, we mute for the web): soft room tone, subtle mechanical keystrokes, one low resolve tone. No music, no voice.

NEGATIVE PROMPT (paste into Veo's negative field):
subtitles, captions, watermark, on-screen UI text changing or warping, morphing or melting interface, garbled letters, gibberish code, extra cursors, duplicated panels, people, faces, hands, brand logos other than Bimax, oversaturated colours, neon, rainbow hues.

VEO SETTINGS: 8s · 1080p (or 4K on Veo 3.1) · image-to-video from the START FRAME · optional 2nd reference = end frame for a cleaner loop. Web: trim to a seamless ~6s loop, export muted MP4 + WebM, first frame ≈ last frame.

Engineering

How the scroll drives the camera

Robust and cheap over clever. Six full-height pinned panels driven by one scroll-progress value — no scroll-jacking, no fragile 3D scene that stalls under load.

  1. One fixed stage, six pinned acts. A fixed backdrop layer holds the "machine"; each panel is a full-viewport section. A shared scrollYProgress (Framer + Lenis, already in the stack) maps 0→1 across the six and drives the camera transform + which surface is docked.
  2. Veo clips are the living backdrop. Each clip mounts as <video muted loop playsinline> behind its panel, revealed and parallaxed as the panel enters. Because they're image-to-video of the real screenshots, the video is the product shot — no separate static image needed.
  3. DOM does the literal state-changes. Text typing, code streaming, the green check, the badge flip, the "3 call sites" pulses — coded as DOM/CSS animation layered over the video, so type stays crisp and the copy is real, editable, and accessible.
  4. Performance guardrails (from prior lessons). Only the active panel's video plays (IntersectionObserver pause offscreen); poster-first so nothing blocks paint; prefers-reduced-motion freezes to a poster still; a ?static flag disables the scroll-camera for screenshotting.
  5. Mobile = the same six beats. The camera move collapses to simple stacked reveals; every panel still reads top-to-bottom with its clip + copy. No horizontal scroll at any width.
Build order

Suggested sequence

  1. Generate 4b first (the CLI hero loop). It's the soul of the piece. In your Chrome, open Gemini/Flow, upload ui-terminal.png, paste prompt 4b (Copy button includes the Style DNA + negative prompt). If it lands, everything else follows the same recipe.
  2. Then 1a, 2a, 3a, 5a, 6a, 6b, 4a. The rest, in narrative order, each image-to-video from its start frame.
  3. Trim + export. Each clip → seamless ~6s loop, muted MP4 + WebM, ~1600px wide, into site/public/media/panels/.
  4. Build the six-panel scroll shell. Rebuild site/src/App.tsx around the pinned-panel model, mount the clips, layer the DOM copy + state-changes, keep the ember/teal system.
  5. Preview, tune the camera curve, ship to Vercel. Verify at 390 / 768 / 1440, reduced-motion, no horizontal scroll — then deploy.
